# Fonts roadmap

Goal: an app can use any font the way a web page can (its own files, installed families,
generic families, every weight, slant, width, feature and axis), text looks as good as in a
browser on the same machine, and the framework never gets in the way: no crashes on odd
input, no limits an app can hit by animating a property, the same result in development, in
tests and in the packaged executable.

Status keys: **done**, **P0** (bug, fix first), **P1** (needed to call fonts complete),
**P2** (expected by some apps), **P3** (nice to have). Each item says where the work goes and
how it is tested (see the TDD rules in `AGENTS.md`).

## Done (2026-10-13)

- `fontWeight` 1..1000, `bold`, `italic`, `letterSpacing`, inherited (`inheritedFont()`).
- `fontFamily`: CSS family lists of app, installed and generic families (`serif`, `monospace`,
  `system-ui`, `emoji`...), quoted or not, case-insensitive; per-character fallback through the
  list, then the system's (fontconfig `FcFontSort` after the list's first system family).
- `registerFont(pathOrBytes, { family, weight, italic })`: TTF, OTF/CFF, TTC (every face),
  WOFF, WOFF2, variable fonts (the whole `wght` range); bytes copied once and deduplicated;
  works with `with { type: "file" }` imports in packaged executables.
- CSS font matching (slant, then the weight rules); faces with the same descriptors are all
  used, in registration order, to fill each other's missing glyphs.
- Synthetic bold (`FT_Outline_Embolden`, 1/24 em, advances unchanged) and synthetic italic
  (shear), for app and system fonts.
- `fontFeatures` (OpenType features, CSS or HarfBuzz syntax) and `fontVariations` (any axis;
  `wght` there wins over `fontWeight`).
- `fontFamilies()`: installed and registered families.
- `<Canvas>` text (and so charts) takes `{ family, features, variations }` and otherwise
  inherits them from the tree; `TextField` and overlays (`layer.parent` is the placeholder)
  inherit them too.
- Color emoji: CBDT/sbix bitmaps and COLRv0, in an RGBA atlas.
- Glyphs larger than the atlas (2026-10-13): bitmaps over 512 px on a side (`MAX_GLYPH` in
  `text.c`) are box-filtered down into the atlas and stretched back by the quad (A8 atlas now
  `GL_LINEAR`, identical at 1:1); used to recurse forever. Test: "a glyph larger than the atlas".
- Animated variable axes (2026-10-13): faces of variable files are evicted LRU when the table
  runs low, at the start of `nb_font_style` (the only point where nothing holds a face), with a
  generation per face slot in the glyph cache key; variation lists are freed when they run low
  (specs and styles dropped). Installed-family lookups are cached (256). `fontStats()` in the
  addon reports the live entries. Tests: "animating a variable axis", "more weights in one frame".
- One `FT_Face` per face shared by its sizes (2026-10-13): `FT_New_Size`/`FT_Activate_Size`, an
  HarfBuzz font per size, LRU over 64 sizes. Cycling 200 sizes (worse than any `fontSize`
  animation): 35 -> 20 us per measure; up to 64 sizes ~1 us, unchanged. The rest is HarfBuzz's
  `hb_face` per size and TrueType's per-size hinting setup. Test: "sizes of one face share it".
- Atlas pages with LRU (2026-10-13): the A8 atlas is a 2048 px texture of four 1024 px pages,
  the color one 1024 px of four 512 px pages (glyph cap 256); the least recently used page is
  wiped, never one used by the current frame; only changed rows are uploaded. A scene over one
  page (30 sizes of a pangram, offscreen): 5.1 -> 0.9 ms per frame; within one page 0.58 ->
  0.40 ms. Test: "a frame with more glyphs than one atlas page".
- Tests: `test/text/fonts.test.tsx` with the box fonts of `test/fixtures/fonts/` (known advances,
  generated by `build.py`), `font-style`, `font-fallback`.

## Core (native)

### Faces, sizes and memory
- **P1: match installed families in `faces.c`.** Every new weight is a new style, and resolving
  it asks fontconfig (`FcFontMatch`, ~0.35 ms) for each system family of the list and the UI
  font: an animated `fontWeight` pays that every frame (measured: 801 weights in 300 ms, while
  1200 new variation strings at one weight take 50 ms). List a family's faces once
  (`FcFontList`: file, weight range, slant) and run the same CSS matching as app fonts.
  Measure with the "animating a variable axis" test and a scene animating `fontWeight`.
- **P2: `unregisterFont(faces)`.** Frees the registry entries and, once no style uses them, the
  faces and the copied bytes. Eviction exists for variable faces (`evict_faces`): extend it to
  the faces of an unregistered file, then free the file and its bytes.
- **P2: limits as warnings, not silent fallbacks.** When a table is full (registered faces,
  specs, faces), print once in development, like the overflow warnings.

### Glyph atlas
- **P2: sharp very large glyphs.** Past 512 px they are downscaled into the atlas and stretched
  back (soft edges at `fontSize` 1000+). Drawing them as a path (`TRIANGLES`) would keep them
  sharp at any size.

### Rendering quality
- **P1: subpixel positioning.** Glyphs are snapped to whole pixels (`roundf` in `draw_glyph`),
  so fractional `letterSpacing`, small sizes and centered text drift and look uneven. Cache
  glyphs at 3 or 4 horizontal phases (part of the glyph key) and draw at the nearest phase.
- **P1: follow the system's rendering settings.** fontconfig gives `hintstyle`, `antialias`,
  `rgba` and `lcdfilter` per pattern (the desktop's font settings write them). Map hintstyle to
  `FT_LOAD_TARGET_*` / `FT_LOAD_NO_HINTING` per face; keep light hinting as the default.
- **P2: gamma / contrast** for A8 coverage (dark text on light backgrounds looks thin, light on
  dark looks bold). Linear blending with a text gamma (Skia uses ~1.2 contrast + gamma 2.2
  approximation); a uniform in the text shader.
- **P2: stem darkening** for CFF fonts at small sizes (`FT_Property_Set(..., "cff",
  "no-stem-darkening", 0)`), as browsers on Linux do.
- **P3: LCD subpixel antialiasing.** Needs RGB coverage and dual-source or per-channel
  blending; not worth it on HiDPI. Only if a user asks.

### Color fonts
- **P2: COLRv1** (gradients, transforms, compositing), which newer emoji fonts and icon fonts
  ship. FreeType 2.13+ exposes the paint graph (`FT_Get_Color_Glyph_Paint`); rasterize it on
  the CPU into the RGBA atlas with our own rasterizer (`src/geometry` has the pieces in TS; in C
  it needs a small paint interpreter). Fall back to the outline in the text color when
  FreeType is older.
- **P3: OpenType-SVG** glyphs (some color fonts): would reuse `src/svg`, so it means asking TS to
  rasterize, which breaks the "C draws text" boundary. Probably never.

### Scripts and layout
- **P1: script and direction itemization.** Runs are split by face only and
  `hb_buffer_guess_segment_properties` guesses one script for the whole run, so Latin + Arabic
  or Latin + Devanagari in the same face can shape wrong. Split runs by Unicode script (with
  common/inherited characters joining their neighbors) and direction before shaping.
- **P1: bidi (UAX #9).** Right-to-left runs are shaped but lines are not reordered. Implement
  the bidi algorithm ourselves (no fribidi: zero dependencies) in TS (line breaking lives there)
  or C; `Text`, selection and `TextField` caret must follow visual order.
- **P1: `lang` prop (inherited).** Sets the HarfBuzz language (`locl` forms: Serbian, Bulgarian,
  Turkish i) and the fontconfig `lang` for fallback, which picks the right CJK glyphs (the same
  codepoint is drawn differently in Japanese, Simplified and Traditional Chinese, Korean).
  Default: the process locale (`LANG`).
- **P2: per-script fallback order.** Ask fontconfig per (family, lang) instead of per family.
- **P3: vertical text** (`writing-mode`). Only with a real use case.

### Metrics
- **P1: real line metrics.** Line height is `ascent + descent`; CSS `normal` adds the line
  gap (`hhea.lineGap`, or the typo metrics when `USE_TYPO_METRICS` is set). Decide the default
  (keep today's for stability, or follow CSS) and expose `lineGap`.
- **P1: decoration metrics.** `underline` is a third into the descent with `fontSize / 14`
  thickness; fonts have `post.underlinePosition/Thickness` and `OS/2.yStrikeoutPosition/Size`.
  Return them from `measureText` (or a new `fontMetrics(font, size)`), use them for
  `underline`, and add `lineThrough` (strikethrough) with the same plumbing.
- **P2: `fontMetrics()` in the public API**: ascent, descent, lineGap, capHeight, xHeight,
  unitsPerEm, for apps aligning icons to text (cap-height centering) or doing their own layout.

### Platform
- **P1: notice fonts installed while the app runs**: `FcConfigUptoDate()` before listing or
  matching, at most once per second; on change, drop styles and fallback sets (same path as
  `registerFont`).
- **P1: the desktop's UI font.** `sans-serif` is fontconfig's default, which is not always the
  font the desktop shows (GNOME's `org.gnome.desktop.interface font-name`, KDE's `kdeglobals`).
  Read it through the XDG settings portal (D-Bus, which the dark-theme item also needs) and
  use it for the UI font and `system-ui`; also the text scaling factor (accessibility).
- **P2: Windows and macOS backends** of the font contract (DirectWrite / CoreText enumeration,
  matching and fallback) when those platforms arrive: `nb_platform_font_path`,
  `nb_platform_font_fallback`, `nb_platform_font_families` are the whole surface.

## TypeScript / framework API

- **P1: an app-wide default family in the theme.** `theme.font` has only `size`. Add
  `theme.font.family` (and maybe `features`), used by `Text`, `TextField` and `Canvas` when no
  ancestor sets one, settable through `setTheme`. Today the workaround is
  `<Window fontFamily="...">`, which works (overlays inherit through their placeholder) but is
  easy to miss in tests that `mount` a component alone.
- **P1: `unicodeRange` option in `registerFont`.** `@fontsource` and Google Fonts ship one file
  per subset (latin, latin-ext, cyrillic...) for the same family and weight. They already work
  by coverage, but an explicit range (CSS `unicode-range`) avoids loading a subset for
  characters it does not cover and makes the order irrelevant.
- **P1: `fontStretch`** (CSS `font-stretch`, 50%..200%): matched against registered faces (a new
  descriptor) and fontconfig's `width`, and set on a `wdth` axis. Condensed families need it.
- **P1: `fontSynthesis`** (CSS `font-synthesis: none | weight | style`), to turn off fake bold
  and italic, e.g. for icon fonts or when a designer wants the closest real face.
- **P2: `fontOpticalSizing`** (CSS default `auto`): set the `opsz` axis to the font size
  when the font has one. Cheap: one more coordinate in `set_variations`, a size-keyed face.
- **P2: high-level variants over `fontFeatures`**: `fontVariantNumeric` (`tabular-nums`,
  `oldstyle-nums`, `slashed-zero`, `diagonal-fractions`), `fontVariantCaps` (`small-caps`, with
  synthesis when the font lacks `smcp`), `fontKerning`. They map to feature strings, merged
  with `fontFeatures` (which wins).
- **P2: `registerFont` from a URL / async `loadFont`**: `await loadFont(url)` downloads, then
  registers. Text keeps the fallback until then (CSS `font-display: swap`), already true since
  registering re-measures.
- **P2: introspection**: `registeredFonts()` (what `registerFont` returned so far) and
  `resolveFont(style, text?)` returning which face files draw a string, for debugging "why is
  this not my font" (also printed by a `NB_TRACE=fonts` mode).
- **P3: `Native.measureText` takes an options object** instead of six positional arguments
  (internal API; `nativeTextMeasurer` is the only caller).

### Text widgets
- **P1: selection and caret inside ligatures and fallback runs.** Selection measures prefixes;
  with a ligature (`ff`) or kerning the prefix width is not the drawn position. Get cluster
  positions from the shaped run (`hb_glyph_info.cluster`) in one native call
  (`measureClusters(text, font) -> offsets[]`) and use them for caret and selection.
- **P2: `TextField` draws `underline`/`lineThrough`** and supports the same font props (it
  already inherits family, features and variations).

## App developer experience

- **P1: `nodebuilder fonts add <family> [--weights 400,700] [--italic] [--subsets latin]`**, like
  `icons add`: looks the family up in the app's `node_modules` (`@fontsource/<id>` or
  `@fontsource-variable/<id>`), writes `src/fonts.ts` with the `with { type: "file" }` imports
  and the `registerFont` calls, and prints the license (OFL) to keep. `fonts list [filter]` lists
  installed `@fontsource` packages. Tests in `cli.test.ts` against a fake `node_modules`.
- **P1: template**: a commented `src/fonts.ts` in `create-nodebuilderjs`, imported first by the
  app entry; the `nodebuilder-ui` skill already documents fonts, add a `nodebuilder-fonts`
  skill (or a section) on picking, adding and licensing fonts, and on testing with them.
- **P1: deterministic tests with app fonts.** Apps that register their fonts in tests get real
  metrics that do not depend on the machine: document `registerFont` + `useRealTextMetrics()` in
  the testing skill, and make `mount`/`screenshot` honor registered fonts (they already do, the
  registry is process-wide).
- **P2: packaging notes**: fonts embedded in the executable (size: a WOFF2 subset is 20-60 KB,
  a full TTF can be MBs; prefer WOFF2 and subsets), licenses copied into the package docs
  (`/usr/share/doc/<name>/`), and a check that warns when an app registers a font by a loose
  path (works in dev, missing in the package).
- **P3: a font picker widget** (`<FontSelect>`): `Select` over `fontFamilies()`, each option drawn
  in its own family. The `text` example has the basic version.

## Testing plan

- Keep the box fonts as the base of every behavior test (exact widths and pixels). Add to
  `build.py` as needed: a font with `opsz` and `wdth` axes, a COLRv1 glyph, a font with
  `smcp`, an Arabic-shaped dummy (or a small OFL subset of Noto Sans Arabic, license recorded),
  CJK `locl` cases with a tiny subset.
- Real-font tests stay `skipIf` the font is missing (`font-style`, `font-fallback`).
- Fuzz `registerFont` with truncated and bit-flipped fixtures: always an Error with a message,
  never a crash (FreeType is robust, but our table parsing (`OS/2`, axes) must be too).
- Performance items carry before/after numbers from the same session (`bun run bench`,
  `bench:dashboard`, the offscreen microbenchmark used for families: measure and draw 2000
  strings, ASCII and UTF-8).

## Order of work

1. Installed-family matching in `faces.c` (animated `fontWeight` without fontconfig per frame).
2. `theme.font.family`, `fontSynthesis`, `fontStretch`, `unicodeRange`, `fontOpticalSizing`.
3. Metrics: line gap, decoration metrics, `lineThrough`, `fontMetrics()`.
4. Subpixel positioning and the system's rendering settings.
5. Script itemization, `lang`, then bidi (the largest item).
6. `nodebuilder fonts add`, template and skill, packaging notes.
7. COLRv1, introspection, async loading, high-level variants.
8. Fonts installed at runtime and the desktop UI font (with the XDG portal work).
